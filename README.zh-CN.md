# 减少信息差（life-guide）

[English README](README.md)

> 🧭 让 AI 在动手之前，先看清技术路线。

`life-guide` 是一个面向技术选择、资料核查和复杂判断的通用 Agent Skill。它让 AI 在急着推荐工具、库、工作流或实现方案之前，先停下来确认真正会改变结论的条件。

## 当 AI 回答得太快

你说：

> 「我想做一个带粒子、字幕和音频响应的技术动画。」

普通回答可能马上列出几个工具。`life-guide` 会先检查：

- 🎞️ 你要的是实时交互，还是最终视频渲染？
- ⚙️ 它运行在网页、合成器、3D 工具，还是桌面应用里？
- 🧩 你更在意高帧率、低延迟、画面质量，还是可重复渲染？
- 🔎 哪些版本、依赖和宿主限制可能阻断交付？
- 🧪 哪个最小 Demo 能先验证最大的风险？

然后再比较 Canvas、WebGL、3D、视频合成和其他相关路线；核对一手资料；给出可以执行的下一步。

## `life-guide` 会改变什么

- 🧭 把候选空间扩展到第一个工具或工作流之外。
- 🔎 分开事实、用户陈述、假设、推断和未知。
- 📚 把会改变决策的主张追溯到官方文档、规则、源码或原始数据。
- ⚖️ 比较成本、耗时、性能、维护、可逆性和机会成本。
- 🧪 在完整制作前，先设计一个低成本验证动作。
- 🛑 写清停止条件，以及哪些新信息会改变当前推荐。

你可以直接问：

> 「这个效果应该用 Canvas、WebGL 还是 3D 工作流？」<br>
> 「我现在的技术栈能不能稳定支持它？」<br>
> 「这个动画库现在还值得用吗？」<br>
> 「我应该先做哪个原型？」

简单问题，直接回答。复杂制作，先拆路线。高影响技术选择，先核对证据和失败分支，再给推荐。

`life-guide` 不承诺唯一正确答案，也不承诺列尽所有可能。它要做的是让 AI 和人，在真正投入之前，看见更多真实可行的路线。

更完整的行为示例见 [`skills/life-guide/references/examples.md`](skills/life-guide/references/examples.md)。

## 6.1.0 输出结构（复杂问题固定四段式）

从 6.1.0 起，复杂问题和多方案问题的回答顺序固定为 **数据 → 导图 → 总结 → 行动或延伸**：

1. **数据区在最前**：按市场、技术、成本、规则分组，每条关键数据写来源、查询日期、适用范围、来源强度和是否原始；判断不混进数据。
2. **导图在数据之后**：覆盖结论、关键分支、依据或未知、下一步；Mermaid 无法渲染时用 3–4 层纯文本树。
3. **总结区精炼**：判断正文约 300 字以内，最多引用 1–2 个数字，逐项标注已核实 / 用户陈述 / 推断 / 未知 / 经验判断。
4. **行动或延伸区在全文最后**：用户要做决定或执行时，写 100–200 字行动区，包含这周做什么、成本、如何验证、当前主推荐、切换条件和最大未知；用户只想了解方向时，写精炼的延伸区，列出尚未展开的路线、会改变排序的未知和下一轮可查方向。

同时生效的两条硬规则：

- **时效性资料必须先检索**：涉及价格、版本、法规、政策、平台规则、软件工具、岗位与市场趋势、舆情评价，先查最新来源再判断，不凭记忆作答；查不到最新资料时写“截至查询日未核实”，不得写“目前最新”。
- **来源强度四档**：原始来源 / 可靠转载 / 仅摘要 / 未取得原文。二手资料不得写成“已核实原文”，仅摘要只能作线索，不作结论依据。

简单事实、纯写作、稳定常识仍走短答，不强行联网、不强行出图。

## 安装（约 3 分钟）

**通用要求：复制整个 `life-guide/` 目录，不要只复制 `SKILL.md`**——参考文件按需读取，缺了规则就不可达。标准源包在 [`skills/life-guide/`](skills/life-guide/)，也可使用发布页的上传 zip（解压后顶层即 `life-guide/`）。

| 平台 | 放置位置 / 导入方式 | 如何确认已识别 |
|---|---|---|
| Claude Code | 项目 `.claude/skills/life-guide/`，或用户 `~/.claude/skills/life-guide/` | `/skills` 查看 |
| OpenAI Codex | `.agents/skills/life-guide/` | `$life-guide` 显式调用 |
| Gemini CLI | `.gemini/skills/life-guide/`，或 `gemini skills install <路径>` | `/skills list`（工作区需先 `/trust`；新增后 `/skills reload`） |
| GitHub Copilot | 项目 `.github/skills/life-guide/`（也认 `.claude/skills`、`.agents/skills`）；个人 `~/.copilot/skills/` | 提问后观察是否加载；可用 `gh skill` 安装 |
| WorkBuddy 本地 | 技能目录下的 `life-guide/` | 技能清单中出现名称与描述 |
| WorkBuddy 开放平台 | **需专用宿主包**，见 [`adapters/workbuddy/`](adapters/workbuddy/)（字段要求不同，未实测上传） | 以上架审核结果为准 |
| 豆包 / 扣子 | 内容映射，不是标准包直装，见 [`adapters/`](adapters/) | 未实测 |

Windows 示例（Git Bash，Claude Code 项目级）：

```bash
mkdir -p .claude/skills
cp -r /path/to/skills/life-guide .claude/skills/
ls .claude/skills/life-guide/SKILL.md
```

**装好后用两道题自验**：

1. 问「巴黎在哪个国家」→ 应直接回答，**不应**追问职业目标或启动调查。
2. 问「我想做一个带粒子和音频响应的技术动画」→ 应先复述已知、指出会改变路线的缺口并按优先级提问，**不应**直接丢出一个工具名称。

两题都符合，说明加载与边界生效；不符合请按 [`CONTRIBUTING.md`](CONTRIBUTING.md) 提交宿主、版本、输入与实际输出。

## 验证边界（请先读这一段再决定是否采用）

- **结构校验通过 ≠ 效果已证明。** 结构检查与静态 CI 只证明包结构、引用与规则文本一致。
- 当前版本已完成结构检查，并有有限的本地自测记录；**跨会话稳定性、自动触发、跨宿主、跨模型和真实用户效果仍未验证**。各平台状态见 [`adapters/`](adapters/)，未实测的一律标注未验证。
- 行为会受到模型、宿主、加载方式、实际读取的参考文件和可用工具影响。同一模型的稳定性必须在相同条件下至少重复三次才能判断；模型没有联网能力时不能核实当前资料。
- 历史行为证据来自 5.x 批次：12 次有技能运行、119/120 行为格通过，但该批次**跨版本、单宿主（ZCode）、单模型（GLM）、手动加载、人工判定**，不能外推到当前版本或其他宿主。
- 各平台状态逐项见 [`adapters/`](adapters/)：文档适配与已实测分开标注，未实测的一律写未验证。
- 本技能可能建议联网检索或读取参考资料；工具安装、账号登录与外部写入需你明确批准，技能本身不承诺「无病毒」「不封号」。
