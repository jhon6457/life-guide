# life-guide 6.1.8 发布前审计

## 当前状态

6.1.8 是本地发布候选版。仓库源包与 WorkBuddy 安装副本均为 6.1.8，21 个运行包文件逐字节一致。GitHub 远程尚未推送本轮修改。

## 本轮已处理

- 易变信息先做时效预判。
- 有检索能力且命中易变事实时，要求实际调用检索工具并记录时效状态、是否检索、查询日期和关键来源。
- 单一、低影响事实核实后可以短答，比较、投入、资格、法规和高影响任务使用四段式，避免无意义展开。
- 四段式顺序固定为：数据 → 导图 → 总结 → 行动或延伸。
- 数据区要求来源、查询日期、适用范围、来源强度和是否原始。
- README 的效果说明改为“结构检查和有限本地自测”，不把它写成稳定效果证明。
- 高影响或难撤回的决定默认做轻量认知偏差检查，并记录模型、宿主、加载方式和工具权限。
- 同一模型的稳定性判断要求相同运行条件下至少三次重复，单次通过不再当作稳定证据。
- 结尾区按用户意图选择行动或延伸，探索方向时不强行编造行动清单。
- 短答、首轮澄清和渐进交付不再对探索型问题强制安排行动。
- 候选覆盖、路线根本差异和条件化引导已接入正式比较，用户提出的路径与 AI 新扩展的路径分开记录。
- 无技能压力基线已出现“截止时间下直接单选并过度使用未充分核实数据”的失败，带技能运行完成了当前资料核验、隐藏路线扩展、证据降级和条件切换。
- 压力场景原始判定记录见 [`tests/skill-pressure-6.1.5.md`](../tests/skill-pressure-6.1.5.md)。
- 监督清单增加核心机制、责任位置和条件化引导检查。
- 数据区与总结区的职责重新分开，正反证据和错误主张状态在数据区处理，判断集中在总结区。
- 对技能包做了个人隐私扫描，未发现个人履历、账号、私人路径或本机目录。
- 总结区固定先显示判断，再显示理由、反方条件和关键未知，减少已核实事实重复。
- 清理文档末尾空行，`git diff --check` 通过。
